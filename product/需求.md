## 1. 产品是什么

面向求职者的**模拟面试练习工具**：按岗位与简历出题、逐题追问、给出可解释的扣分与改进建议。

**不是**招聘筛选工具，**不是**简历真实性鉴定。评分只用于练习反馈。

### 1.1 核心流程

**当前可用闭环（011）**：管理员登录 → 简历上传/原文核对 → 手填相对权重 → 数据库知识题（1–20）→ 逐题文字回答 → 历史回看。以下10题、追问、评分为后续规划，本轮不执行。

```
设置（岗位 / 权重）→ 简历（上传 / 解析 / 确认）→ 组卷 → 10 题面试 → 追问（≤2 层/题）→ 报告
```

- 常规模式固定 **10 题 = 5 道八股 + 5 道简历拷打**；追问**不计入** 10 题。
- 专项训练只出知识题，不限题量。
- 用户可打字作答，不必录音（文字是一等公民，不是降级）。

### 1.2 非目标

不做公开注册、动作识别、本地模型推理、公网开放、付费、真人视频面试（1.0）。本轮已加入本机管理员登录，资源绑定账号。

## 3. 题库与组卷

### 3.1 题库现状

10 个知识点池，每池 20 题，**共 200 题，`stage: seed`（占位，未人工校验）**。正式目标 100 题/池。

| topicId | 名称 | 现状 | topicId | 名称 | 现状 |
|---|---|---|---|---|---|
| `js` | JavaScript | 20 | `algorithm` | 数据结构与算法 | 20 |
| `vue` | Vue | 20 | `database` | 数据库 | 20 |
| `react` | React | 20 | `os` | 操作系统 | 20 |
| `html` | HTML / CSS / 布局 | 20 | `java` | Java / JVM | 20 |
| `network` | 计算机网络 | 20 | `engineering` | 前端工程化 | 20 |

`ts`、`behavioral` 暂缺（题量 0，自动置灰）。历史「12 池 / 700 题」口径已作废。

### 3.2 题目结构

```ts
interface TopicBankFile {
  topicId: TopicId;                 // 池级声明，题目内不重复写
  name: string;
  stage: 'seed' | 'curated';        // seed=占位可替换；curated=正式
  version: number;
  questions: Question[];
}
interface Question {
  id: string;                       // q_<topic>_<4位>
  difficulty: 1 | 2 | 3;
  mode: 'oral' | 'oral_scenario';
  text: string;                     // ≤120 字，问号 ≤2 个
  expectedPoints: string[];         // 3–6 条，单条 ≤60 字
  followUpHints?: string[];
  tags: string[];
  timeLimitSec: number;
  verified: boolean;
  // topicId 由加载器注入；contentHash 构建时按 text 计算
}
```

**可用题集**（唯一写法，代码里不要另写一套）：

```
usable(pool) = pool.stage === 'seed'
             ? pool.questions
             : pool.questions.filter(q => q.verified)
```

seed 池被抽中时，`PaperPlan.warnings` 必须追加「占位题库，质量未校验」，**报告页展示，不可隐藏**。

### 3.3 岗位权重与配额

权重是**相对重要性，不是题量**：`TopicWeight { topicId, weight, minCount?, maxCount? }`，`maxCount` 默认 2。

分配算法（最大余额法）：

1. 剔除 `weight=0`，按 `weight/Σweight` 归一化；
2. `quota = floor(count × share)`；
3. 余额按小数部分降序补 1；
4. 应用 `minCount` / `maxCount`；因上限产生的缺口回填给次高权重未达上限者；
5. 同余数按 `topicId` 字典序稳定排序（保证同 seed 可复现）。

**算例（必须与实现一致）**：`vue20 / network20 / react20 / engineering20 / java10`，`count=5`

| 步骤 | 结果 |
|---|---|
| 归一化 | 0.2222 ×4，0.1111 |
| 基础配额 | vue1 / net1 / react1 / eng1 / java0（合计 4） |
| 余额 | 空位 1 个，java 小数 0.5555 最大 → 补给 java |
| 最终 | **vue1 / network1 / react1 / engineering1 / java1** |

> 常见误解：以为「4 个 1 已满 5」。只占 4 个位置，第 5 个属于 java。

### 3.4 组卷与降级（四级级联，不许跳步）

| 级 | 情形 | 处理 |
|---|---|---|
| L1 | 某池可用题 < 配额 | 缺口转给次高权重、未达上限的池 |
| L2 | 全部触达 `maxCount` | 放宽到 2，允许同池 2 题 |
| L3 | 仍不足 | **减题**：5→4→3 道八股，总量不低于 **6 题**，开考前明示 |
| L4 | 减到 6 题仍凑不出，或覆盖 <2 主题 | **拒绝开考**，不生成残卷 |

- 单题去重重抽 ≤5 次，超限进入下一级，禁止死循环。
- 主题覆盖约束：`count ≥4` 时 ≥3 个主题；`<4` 时放宽到 ≥2 并写 warning。

### 3.5 简历拷打题（不走题库）

```ts
interface ResumeProbe {
  id: string;
  source: 'suspicion' | 'project' | 'gap_fill';
  target: string;                 // gap_fill 固定 'general'
  question: string;               // ≤60 字
  anchorQuote: string | null;     // 简历题必非空；gap_fill 必为 null
  severity: 1 | 2 | 3;
  confidence: number;
}
```

生成顺序：`suspicions`（按 severity×confidence 取前 3）→ 项目深挖（4 选 2 模板）→ `gap_fill` 补齐。

**硬规则**：
- `suspicion` / `project` 属**简历题**，`anchorQuote` 必须逐字来自简历原文；
- `gap_fill` 属**通用深挖题**，引用必须为 `null`，**不计入简历题数量**；
- 简历为空时 5 道全为通用题，报告显示「简历题 0 道」，不得伪造引用。

## 4. 评分

### 4.1 维度与权重

| 维度 | 代码 | 1.0 权重 | 2.0+ | 打分方 |
|---|---|---|---|---|
| 内容质量 | `CONTENT` | 40 | 40 | AI |
| 表达流畅 | `FLUENCY` | 15 | 15 | **纯规则**（无 AI 修正） |
| 口头禅 | `FILLER` | 10 | 10 | 规则 |
| 动作表现 | `BODY` | **0（未启用）** | 10 | 规则 + 姿态模型 |
| 简历追问 | `RESUME` | 15 | 15 | AI 主 + 规则 |
| 岗位匹配 | `FIT` | 10 | 10 | AI |

### 4.2 量纲（必须严格执行）

```
dimScore_100 = raw / rawMax × 100      // CONTENT 40、RESUME 15、FIT 10、FILLER 100、FLUENCY 100
finalScore   = clamp( Σ(dimScore_100 × effectiveWeight), 0, 100 )
effectiveWeight = w / Σ(w for w > 0)
```

同一维度**不得重复加权**。1.0 中 `Σw = 90`，故 CONTENT 实际占比 44.4%。

### 4.3 逐维状态

| status | 参与聚合 |
|---|---|
| `SCORED` | ✅ |
| `NEEDS_REVIEW` / `NOT_APPLICABLE` / `NOT_ENABLED` | ❌ 从分母剔除并重新归一化 |

**禁止**用 0 或满分填充缺失维度。

### 4.4 覆盖率与区间

- 覆盖率 = 参与聚合维度权重和 ÷ 全部维度权重和。
- **覆盖率 <50% → 只输出区间 `totalScore ± 8`**，`scoreKind='interval'`，不给点值。
- ≥50% 才输出点值。

### 4.5 符号与封顶（D03）

- **JSON `points` 一律正数**，方向由数组决定：`deductions` 减、`bonuses` 加。
- 封顶顺序固定：**单条规则 → 单维度 50% → 维度满分 100**。
- `bases` 必填：`base − Σ扣 + Σ加 = score`，容差 ±0.5，超出即 `NEEDS_REVIEW`。
- 维度分与总分保留 1 位小数，中途不舍入。

### 4.6 扣分规则（节选核心，完整表见 `docs/archive/pm/04-评分原则与规则表.md`）

| ruleId | 触发 | 分值 | 封顶 | 误判保护 |
|---|---|---|---|---|
| `FIL-001` | 填充词密度 ≥6 次/分，连续 2 个 60s 窗 | 扣 3 | -10 | 词置信度 <0.70 不计（推导置信度不可用，见 G11） |
| `FIL-002` | 密度 ≥10 次/分 | 扣 5 | -10 | 与 001 取高档不叠加 |
| `FIL-003` | 同词连续 ≥3 次 | 每次扣 0.5 | -3 | 需词级时间戳 |
| `FLU-001` | 单题语速 <120 字/分 | 每题扣 3 | -9 | 时长 <10s 或字数 0 跳过 |
| `FLU-002` | 单题语速 >320 字/分 | 每题扣 2 | -6 | 丢字导致虚高则跳过 |
| `FLU-003` | 单次静默 ≥8s | 每次扣 1 | -3 | 断网/设备导致不计 |
| `CNT-001` | 答非所问 | 扣 15 | — | 必须引用原文，置信度 <0.65 不扣 |
| `CNT-002` | 只复述概念无案例 | 扣 8 | — | 需指出缺失细节类型 |
| `RES-001` | 疑点追问后仍无可验证细节 | 每疑点扣 6 | — | 疑点置信度 <0.60 不扣，只进追问队列 |
| `RES-002` | 回答与简历直接矛盾 | 扣 12 | — | 须双引用 |
| `FIT-001` | 能力项覆盖 <30% | 扣 10 | — | 词典需人工确认 |
| `BODY-001` | 摸头/挠头 ≥3 次/分（2.0） | 每次扣 2 | -8 | 连续 ≥3 帧、置信度 ≥0.75 |

加分：`BON-001` STAR 完整 +2/题（封顶 +6）、`BON-002` 量化结果 +1/题（+4）、`BON-003` 追问补新证据 +2/次（+6）、`BON-004` 动作稳定 +3。

### 4.7 防误判总则（优先级高于一切扣分）

| # | 规则 |
|---|---|
| G1 | 低置信度不扣分（词 0.70 / AI 0.65 / 姿态 0.75） |
| G2 | 网络、超时、429、空结果 → `INCONCLUSIVE`，不计分 |
| G3 | 动作事件需 ≥3 帧、≥2fps |
| G4 | **任何扣分必须带 evidence**，无证据不生效 |
| G5–G7 | 单维封顶 50%；300ms 去重；不可评估帧整段排除 |
| G8 | 不评外貌、年龄、性别、婚育、口音、残障；出现即 P0 缺陷 |
| G9 | 等式校验不过 → `NEEDS_REVIEW` |
| G10 | 单题 `confidence <0.60` 或有效字数 <20 → 只给区间 |
| **G11** | **推导置信度只能触发复核/不可评估**，不得通过门槛、不得写入 `RuleEvent.confidence`；词级概率缺失时相关规则整体不可用（D08） |

### 4.8 报告契约

```json
{
  "scoringVersion": "1.0.0",
  "scoreKind": "point",
  "totalScore": 78.4,
  "totalScoreRange": null,
  "coverage": 0.889,
  "dimensions": [
    { "code": "CONTENT", "rawMax": 40, "raw": 32.8, "weight": 40, "score": 82.0, "status": "SCORED" },
    { "code": "BODY", "rawMax": 100, "raw": null, "weight": 0, "score": null, "status": "NOT_ENABLED" }
  ],
  "deductions": [
    { "ruleId": "FIL-001", "dimension": "FILLER", "points": 3, "occurredAtMs": 128400,
      "actual": 7.2, "threshold": 6.0, "unit": "次/分钟",
      "evidence": "额……那个，我当时主要是负责这个模块", "confidence": 0.91, "status": "APPLIED" }
  ],
  "bonuses": [],
  "needsReview": false,
  "reviewLog": []
}
```

事件 `status`：`APPLIED | WAIVED | INCONCLUSIVE | PENDING_REVIEW`（仅 `APPLIED` 计入）。

报告必须展示：总分、六维、扣分明细（可展开到时间点）、加分、逐题回顾、简历疑点、`warnings`、口径版本。

## 5. AI

### 5.1 三个任务

`parse_resume`（简历结构化）、`score_answer`（逐题评分+追问）、`final_report`（总结）。

### 5.2 硬边界

- 不得编造经历；所有简历判断必须逐字引用 `rawSnippets`（≤80 字）。
- 不得人身攻击；用事实陈述（「时间存在冲突」而非「你在造假」）。
- 不评外貌、年龄、性别、婚育、口音、地域、学历出身。
- 追问：L1 澄清事实 → L2 追问细节 → L3 压力测试；**每题 ≤2 层**，一次一问。
- 简历拷打只挑 1–2 个高置信度疑点，三段式：引用原文 + 指出冲突 + 请给可验证细节。

### 5.3 输出必填（`score_answer`）

`status / confidence / bases / scores / deductions / bonuses / followUp / resumeFlags / improvements / needsReview`

- `scores.filler`、`scores.body` 固定 `null`（不由 AI 给）。
- `points` 为正数；每条扣分带 `evidence` 与 `confidence`。
- 后端校验：JSON Schema → 等式 → 原文引用存在性 → 区间越界即拒。

### 5.4 失败结构（`parse_resume`，D14）

```json
{ "ok": false, "code": "E_OCR_LOW_QUALITY", "reason": "ocr_quality_low",
  "partial": { "rawText": "…" }, "needsManualInput": true, "message": "图片可能不清晰，请重拍或粘贴文字" }
```

成功与失败**不共用结构**；成功结构补 `profile.summary`（≤120 字）。

## 6. 隐私与密钥（CR-1.0-008修订）

**008历史决定（已被011替代）**：曾为本机单用户无登录。011现已创建管理员与会话表，使用Cookie鉴权和资源归属校验，不使用JWT、不开放注册。

| 事实 | 说明 |
|---|---|
| 本地存储 | 简历、面试与报告存入本机Oracle；音频存本机后端磁盘。当前不提供登录隔离，只供本机使用 |
| 第三方处理 | 选用云识别/评分时，必要简历文本和录音发送至百度/DeepSeek，上传前明确告知 |

密钥全部在后端环境文件；前端无直连模式。API默认127.0.0.1供本机常规流程使用；网络攻击防御与非常规使用处理移到3.0。数据库连接账号不是产品账号；运行时不得使用SYS/SYSTEM/PDBADMIN。

### 6.1 数据存储

| 数据 | 落点 | 保留与删除 |
|---|---|---|
| 简历文本/结构/疑点 | FACE_RESUMES | 直到用户删除；原始PDF/图片解析后丢弃 |
| 会话/逐题/追问/转写 | FACE_SESSIONS/FACE_TURNS | 状态与输入快照持久化；删除会话覆盖从属记录 |
| 音频 | 本地磁盘；FACE_AUDIO_ASSETS保存元数据 | 默认7天；元数据跟踪文件清理状态，过期音频不影响报告 |
| 评分事件/报告快照 | FACE_RULE_EVENTS/FACE_REPORTS | 分数只由后端shared内核聚合；历史快照不静默重算 |
| 审计 | FACE_AUDIT_LOGS | 只存必要动作/资源ID/结果，不存正文、音频或密钥；期限上线前另定 |

删除最终必须物理清除用户内容与磁盘文件。删除请求时间只作为故障恢复标记，不代表已物理清除；文件失败时不得返回“已完全删除”。外键无级联盲删，后端按依赖顺序清理，避免DB已删但磁盘孤儿。复用简历被会话引用时须先解绑或删除关联会话；不得静默破坏其他历史。

2.0再启用账号/权限、队列、本地模型、动作识别及对象存储。数据库/文件适配器隔离具体实现。

## 12. 快速核心闭环（CR-1.0-011，当前最高优先级）

需求方授权：首次进入简历上传；Word/PDF等文字文件，百度OCR与原文核对、持续保存；新增admin账号登录鉴权，资源绑定账号；数据库题库按手填权重出题并文字作答，本轮不评分；导航移到顶部，使用frontend-design-codex更新界面。覆盖旧静态阶段/无登录限制，不实施公网攻防。

本轮：Word(.doc/.docx)、PDF、UTF-8 TXT；原文不可被AI润色，保留提取原文、逐页OCR及用户确认文本。PDF逐页调用百度OCR；Word/TXT直接提取原文，不假称OCR。真实云调用取决于本机配置与账户额度；缺Key显示配置提示。简历、会话、回答均绑定当前登录用户；题库公共但读取需登录。仅本机创建一个admin，不开放注册；初始口令来自被忽略配置，数据库只存scrypt哈希。登录使用HttpOnly cookie与数据库会话，退出/过期不可继续访问。

所有私密配置集中apps/api/.env；数据库、百度、初始管理员、cookie时长均由此读取。修改后重启生效，禁止重复多处配置。允许本轮新增迁移/后端依赖/接口/测试，允许在既有专用Oracle schema执行必要的非破坏性新增迁移并导入200题，不重跑001、不删已有数据。


### 12.1 当前实现边界与验收

- 初始管理员由本机环境配置初始化，密码以 scrypt 哈希保存；仅此管理员入口，不提供注册。简历和练习均按 owner_id 限定，未登录返回401，非本人资源按404处理。
- 允许 .doc / .docx / .pdf / UTF-8 .txt；默认4MB，PDF最多10页，可在后端统一配置。Word/TXT本机提取，扫描Word请转PDF；PDF按页发送百度。原始提取输出不自动润色或补全经历。
- 原件按账号和生成ID保存至本机私密目录；元数据、raw_text、edited_text、逐页原文存在Oracle。两类存储共同备份，不需要NoSQL。当前长期保留，不实现删除入口与自动过期任务。
- 识别原文与确认文本分开显示；支持复制、导出原文TXT、下载原件、保存修订副本，原文不覆盖。OCR失败保留原件与错误状态，可稍后重新识别。
- 题目启动时幂等导入Oracle，仅补缺失种子，不覆盖数据库编辑；请求时只从数据库读取。种子题质量未审核，不隐藏提示。权重是0–100相对份数，0不抽取；默认5题，1–20题。关联简历仅保存归属，不据此生成简历题。
- 文字回答非空、最多20000字符，逐题显式保存，可以修改、刷新恢复。全部保存后标记练习完成，不产生分数/评分事件/AI报告。
- **用户已选择先接口与模拟联调**：百度真实凭证缺失时不伪造输出；测试替身只存在测试，不是运行时模拟开关。真实OCR尚未验收。
