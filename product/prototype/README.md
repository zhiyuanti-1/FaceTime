## 给 agent 的读图方法

1. 用 `read_image` 打开 PNG（1440×900），按上表定位到对应章节。
2. 对照下面「6 条不可改点」逐条检查；**布局可调，这 6 条不可改**。
3. 发现图文不一致时，以 `product/需求.md` 为准，并同时改图和文档。

## 6 条不可改点

| # | 约束 | 为什么 |
|---|---|---|
| 1 | BODY 显示「未启用」，不显示 0 | 0 分会被误读为"被扣光" |
| 2 | 扣分显示「扣 3」而非「-3」 | 与 `points` 正数口径一致 |
| 3 | 报告保留占位题库与降级说明 | 不可隐藏不利信息 |
| 4 | 失败态用页内内联提示 | 面试流程禁止 alert |
| 5 | 权重预览与配额算法同源 | 避免"预览 5 题、实际 4 题" |
| 6 | 追问不计入 10 题 | 统计口径，影响报告 |

## 刻意体现的几条"设计决定"

1. **不显示 0 分**：BODY 未启用时画灰色「未启用」，不打 0。
2. **扣分写"扣 3"不写"-3"**：与 `points` 正数口径一致（D03）。
3. **占位题库提示常驻**：首页、报告都保留，不因难看而隐藏。
4. **权重预览要与算法一致**：预览按最大余额法算，需求 §3.3 冻结算例中 `java 10` 为 1 道；原 PNG 还保留旧预览，静态 UI 按最新需求修正。
5. **失败态先画**：08 才是这版最容易漏的页面，先定失败再定成功。
