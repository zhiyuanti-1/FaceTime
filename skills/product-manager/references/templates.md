# 模板集

四个模板，覆盖 90% 的 PM 交付。复制后删掉反引号里的说明。

---

## 1. 需求受理单

```markdown
# CR-<版本>-<序号> <一句话标题>

> 版本 | 类型（新增/删除/调整/规划/评分/提示词）| 优先级 | 日期
> 假设声明（若为推断）：A1 … ；若错误，影响 …

## 原始描述
<用户原话，不改写>

## 判断
<为什么归到这个类型与版本>

## 八面影响
| 面 | 影响 | 理由 | 需回归 |
|---|---|---|---|
| 前端 / 后端 / API / 数据 | | | |
| 评分 / 提示词 / 部署 / 隐私 | | | |

## 改前 / 改后
| 维度 | 改前 | 改后 |

## 契约变化
<字段、枚举、错误码、版本号；无则写"无">

## 验收
| # | 验收项 | 判定方式 | 通过标准 |

## 回滚
<级别 L1–L4 + 具体步骤>

## 置换
本期减掉：____ ｜ 或延期：____ 天

## 待确认
| # | 问题 | 默认值 |
```

## 2. 规则定义表

一条规则一行，缺列即未完成。

```markdown
| 规则 ID | 触发条件（时间窗+阈值+置信度） | 判定式 | 分值 | 封顶 | 误判保护 | 证据要求 |
|---|---|---|---|---|---|---|
| `XXX-001` | 60s 窗内 ≥6 次，连续 2 窗 | count/min | -3 | 单维 50% | 置信度 <0.7 不计 | 原文片段 ≤80 字 |
```

配套三句必须写在表上方：

- 量纲：各维度统一换算到 0–100 后再加权，同一维度不重复加权。
- 状态：`SCORED` 才参与聚合，其余剔除分母并重新归一化。
- 覆盖率 <X% 时只给区间，不给点值。

## 3. 验收清单

```markdown
## 验收清单（提测前逐条过，附证据）

| # | 验收项 | 判定方式 | 通过标准 | 证据 | 状态 |
|---|---|---|---|---|---|
| 1 | 主流程闭环 | 手工跑 1 次 | 从入口到结果无阻断 | 录屏 | ☐ |
| 2 | 异常路径 | 断网/超时/配额耗尽 | 有提示且可继续 | 截图 | ☐ |
| 3 | 降级路径 | 逐个断开依赖 | 仍能产出结果并标注 | 录屏 | ☐ |
| 4 | 数据一致性 | 重启后复查 | 记录与设置都在 | 截图 | ☐ |
| 5 | 性能 | 计时 10 次 | P95 ≤ 目标 | 表格 | ☐ |

## 未验证项（必须明写）
- <没跑的检查、没测的场景、没有的数据>
```

**规则**：没跑的检查必须明写，不许默认通过。

## 4. 状态汇报（业务视角）

```markdown
# 进度（<日期>）

## 一句话
<能用 / 不能用，差什么>

## 现在能做什么
<用户点一下能看到什么；不夸大>

## P0（缺了不成立）
| # | 功能 | 现状 | 做完的判据 |

## P1（能用但不好用）
## P2（可延后）

## 里程碑
| 里程碑 | 内容 | 用户什么时候能自己用 |

## 技术现状（≤3 行）
<只写阻塞业务的部分，附技术文档链接>
```

**禁区**：工时、工具名、建表、驱动、workspace、依赖版本 —— 这些进技术文档，不进这里。

## 附：文档合并的标准动作

被要求"合并文档"时照此执行，不要凭感觉删：

```markdown
1. 盘：列出所有文件 + 每个文件唯一负责什么（重复的标出来）
2. 定：确定目标份数（≤5）与每份的边界（负责什么/不负责什么）
3. 搬：逐段搬运，给每段找归属；找不到归属的 → 待补充区
4. 验：跑链接检查 + 关键词扫描（确认无第二处定义）
5. 归：旧文件移入 archive/，在进度文档记"旧 → 新"映射
6. 删：确认归档可读后，删除正文副本
```

第 5 步不能省——**归档不是删除**，是给"当时为什么这么定"留证。
