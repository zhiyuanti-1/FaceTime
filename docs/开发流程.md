# 开发流程

> 2026-11-06 · CR-1.0-037 · 当前从空工程重新实施。

## 1. 开工

先检查 git status --short，依 AGENTS.md 阅读需求、技术约束、开发流程、进度、原型索引。保护已有修改，历史记录仅追溯，当前授权以用户指令为准。

默认版本 1.0；按功能变更 CR、评分 SR、提示词 PR、缺陷 HF 编号。未说明的非关键选择用显式假设推进，不反复询问已授权动作。

## 2. 设计与任务卡

新功能或跨模块调整先提交 Mermaid 职责、关系和调用流，经确认后实现；调整设计须再确认。缺陷修复和不改变设计的维护例外。新增目录、公共模块、依赖、脚本先说明路径、职责及不能复用的原因。普通业务文件沿既有目录即可。

编码前在进度填写：版本/编号/端、目标、本批范围、保留行为、需求章节/复用入口、接口和数据变化、影响文件、成功/失败/恢复验收、验证命令、风险与回退。

八面评估逐项写清前端、后端、API 契约、数据结构、评分、AI 提示词、部署、隐私。行为变更先改需求再改代码。

## 3. 实现顺序

每批一个可验证行为，先最小样例再推广。功能后端先交付可验证接口，下一对话接前端；用户明确授权跨端时可同轮处理（037 为空工程重建例外）。页面不代替后端业务，接口缺口回后端。

修改先读调用方和相关测试，修复先复现；每批审查 diff 与相邻路径。连续两次无改善时重新定位，不堆临时补丁。必要重构同步调用方、配置、测试和文档。

兼容旧版本/数据/协议须先明确场景、期限、移除条件与替代方案；未确认不实现。一次性探针和脚本用完删除，正式测试资产保留；重置中已删除业务的专用测试按用户范围一同撤除。

## 4. 验证与交付

功能优先，小批验证受影响路径，按需类型检查或构建；不默认完整 npm run check/全量测试，不扩建测试/CI/门禁。前端记录浏览器验证，后端区分单测、真实 Oracle 加模拟 AI、真实云联调。未运行和失败项如实记录，不用模拟结果冒充实际能力。

公开提交前仍执行保密检查。不得自动提交、推送、发布或新建聊天。代码回退限本轮修改；数据库 DDL、物理文件删除不能靠 Git 或 ROLLBACK 恢复。

## 5. 文档

唯一 AI 入口 AGENTS.md。现行事实分别写在 product/需求.md、docs/技术约束.md、docs/开发流程.md、docs/进度.md、product/prototype/README.md；根 README 作索引和启动指引。不新建目录 README、平行规范入口或临时交付报告。

代码、配置、接口和注解变更同批同步中文说明、相对链接及文末记录。docs/archive 为历史依据，不覆盖当前决定。重建前完整记录仍可从 Git 历史追溯。
