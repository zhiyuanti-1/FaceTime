## 1. 变更原因

组卷算例本身算错、空简历场景既要求"5 道通用题"又要求"每道题引用简历原文"，两者不可能同时成立；上传告知把"本地保存"和"上传第三方"混为一谈。三者都会让实现方在无解约束里打转。

## 2. 改前 / 改后

| # | 台账 | 改前 | 改后 |
|---|---|---|---|
| 1 | D06 | 算例称 `vue20/net20/react20/eng20/java10` 下 java=0，且"已满 5" | 4 个 topic 各 1 = 4 个位置，第 5 个按最大余额（java 0.5555）归 java。**结论反转为 java 出 1 道** |
| 2 | D06 | 余额补位后不足时无规则 | 按「次高权重且未达 maxCount」继续补，允许同池 2 题；同余数按 topicId 字典序 |
| 3 | D07 | 空简历出 5 道 gap_fill，同时要求 `anchorQuote` 非空 | **两类题分开计数**：`suspicion/project` 为简历题（引用必非空）；`gap_fill` 为通用深挖（引用必须为 null），不计入简历题 |
| 4 | D12 | 只放宽 `maxCount`，无终止条件 | 四级级联：L1 转移缺口 → L2 放宽上限 → L3 减题（不低于 6 题，需明示）→ L4 拒绝开考。重抽单题 ≤5 次 |
| 5 | D01 | "1.0 全本地处理，数据不出浏览器" | 两种事实分开表述：①数据保存在本机浏览器；②简历文本与录音会上传第三方。上传前告知 |
| 6 | D14 | 解析失败复用成功结构，`summary` 缺失 | 失败用独立结构 `{ok:false, code, reason, partial, needsManualInput}`；成功结构补 `profile.summary` |

## 4. 接口 / 数据结构变化

- `ResumeProbe.anchorQuote: string | null`；`target` 在 `gap_fill` 时固定 `'general'`。
- `PaperPlan` 新增可按需统计 `resumeProbeCount` / `generalProbeCount`。
- 解析失败结构为独立联合类型，**不复用 `ResumeProfile`**。
- `ResumeProfile.profile` 新增 `summary: string`。

## 5. 对既有功能的影响

seed 题库 200 题不受影响；组卷侧无历史数据，不做兼容层。

## 6. 验收标准

- [ ] `vue20/net20/react20/eng20/java10` + count=5 → `{vue:1,network:1,react:1,engineering:1,java:1}`
- [ ] 全池触达 maxCount 时进入 L2 而非报错；L3 减题后总数 ≥6 且 `warnings` 有记录
- [ ] L4 拒绝时返回可操作提示，不生成残缺 `PaperPlan`
- [ ] 空简历 → 5 道 gap_fill，`anchorQuote` 全为 null，报告显示「简历题 0 道」
- [ ] 有 3 疑点 + 2 项目 → 3 简历题 + 2 简历题（project 也算简历题），引用全部非空
- [ ] 解析失败返回 `ok:false`，前端直接进手填，不读 `profile`
- [ ] 上传页同时出现「本机保存」与「上传第三方」两句话，且可点开看详情

## 7. 风险与回滚

| 风险 | 缓解 | 回滚级别 |
|---|---|---|
| 减题让 10 题变 6 题被质疑偷工减料 | 开考前明示题量 + 报告 `warnings` 留痕 | L1（关闭减题，改为直接拒绝） |
| 简历题计数变化影响报告口径 | `resumeProbeCount` 显式字段，不靠推断 | L2 |
| 上传告知文案改动影响转化 | 告知放在解析前一步，不阻断流程 | L1（文案开关） |

## 8. 等量置换

无新增功能，属口径修正；不占用 1.0 范围。工作量并入 R6（组卷）与 R7（简历）。
