# 部署与 CI/CD 预留

## 当前与 1.0

当前无运行配置、容器、CI YAML 和启动命令。deploy 与 .github/workflows 只有说明。1.0 仅本地自用 Vite 开发代理；dist 是静态资源，不含代理。禁止将开发/preview 服务公网开放或用 direct 的个人 Key 提供公共服务。

## 2.0 服务边界

前端静态包、NestJS API、Postgres、对象存储、Redis任务、Python推理分别配置。数据库/队列/worker 仅私网；模型资源与 CPU/GPU 预算单独核算。数据库迁移为可观测的一次性任务，不由每个副本并发运行。开发、测试、生产凭证和数据隔离。

## 3.0 初始生产拓扑

```text
公网 HTTPS → Nginx/网关 → 静态资源 / API
私网 API → Postgres / 对象存储 / Redis
私网 worker → 模型资源 / 受控云端供应商
```

先采用容量验证的单机 Docker Compose 或托管容器，集群按吞吐与可用性证据再评估。域名、地域、预算、GPU、并发、RPO/RTO 未确定，不能在文档中假定已购置或满足指标。

## 未来 CI/CD 顺序

1. 安装锁定依赖，类型/静态/格式检查。
2. 单元、契约、集成与题库校验；AI固定fixture回归。
3. 构建前端/镜像，扫描泄密、依赖、许可证与镜像漏洞。
4. 生成不可变制品、版本清单与哈希，密钥不得写入构建层或前端。
5. staging 迁移与E2E、降级演练、备份恢复、兼容检查。
6. 在用户授权发布范围内执行灰度与健康门禁，观察错误率/队列/成本/延迟；失败回滚。

后续脚本命令由实际实现确定，本轮不创建可执行流水线。

## 必须具备

TLS与证书轮换、上传限制、入口限流、服务端配额、Secret注入、只读/最小权限账户、结构化脱敏日志、请求关联、延迟/失败/预算告警、就绪与存活检查、优雅终止和队列排空。健康端点不能泄密或发付费请求。

备份必须含数据库与对象一致性策略、加密、权限、恢复演练、删除记录重放。迁移遵循扩展→迁移→收缩，旧制品在回滚窗口可读新数据。

## 回滚

沿 PM-02：L1配置≤5min，L2制品≤15min，L3数据≤2h，L4密钥/隐私止损≤5min为目标，必须演练后才能承诺。L3须备份与恢复/反向迁移方案；破坏性操作不能只靠切旧镜像。历史评分不因回滚静默改口径。
