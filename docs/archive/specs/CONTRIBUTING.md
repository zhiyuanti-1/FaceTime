# 协作、提交与评审

业务流程事实源为 PM-00/02/03；本文件补技术操作约束。当前仅文档阶段。

## 分支与提交

分支 feat/<编号>-<描述>、fix/<编号>-<描述>、docs/<描述>、chore/<描述>；小步提交，禁止夹带无关改动。commit：type(scope): 描述，type 使用 feat/fix/docs/refactor/test/chore；破坏性变更标 ! 并说明迁移。CR/SR/PR/HF 放正文关联；此处 PR-编号指提示词变更，与 GitHub pull request 区分。

有审批状态的 PM 编号不得随意复用或伪造。本次技术 ADR 独立编号，不冒充 PM 已确认变更。

## PR 必填

- [ ] 问题、触发条件、变化后的行为与目标版本清楚。
- [ ] 关联 CR/SR/PR/HF 或纯技术 ADR，并完成八面评估。
- [ ] 前端、后端、API、数据、评分、提示词、部署、隐私八面均写影响/不影响及理由。
- [ ] 没有命中未冻结契约；实现路径与文档一致。
- [ ] DTO、Schema、错误码、版本与兼容/迁移已同步。
- [ ] 相关验证有命令/环境/结果，未执行项明确说明。
- [ ] 降级、取消、低置信度和不可评估路径可验证。
- [ ] 没有秘密与真实个人数据；日志/导出已脱敏。
- [ ] 回滚策略、制品/配置版本与数据影响明确。
- [ ] 文档和 Changelog 更新；评分/提示词改动有回归证据。

## 评审重点

必须检查依赖方向、外部输入校验、重试层数、缓存隔离、扣分证据、同事件去重、历史快照与删除完整性。禁止只看页面效果。原文错误先以变更流程修正文档，并在同一实现变更中同步契约；不通过测试迁就错误算例。

## 完成与发布

符合 DoR 才进入相关业务开发，符合 PM DoD 才验收。当前文档初始化只检查目录、文档和链接，不宣称主流程/性能/评分验收完成。发布、迁移、对外消息等执行按用户授权范围进行；本规范不引入额外的常规可逆工作审批。
