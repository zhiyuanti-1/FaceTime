# 代码生成规范

## 生成前与范围

必须确认版本、需求/变更、验收与命中差异。未冻结业务规则不写实现。先定义输入、输出、错误、降级和边界再编码。当前阶段仅文档与说明占位；后续实现必须另有任务授权。

## 命名

| 对象 | 必须遵循 |
|---|---|
| 目录/普通文件 | kebab-case |
| React 组件/文件 | PascalCase，如 ScoreReportPanel.tsx |
| Hook | useXxx；文件 use-xxx.ts |
| 函数/变量 | camelCase；函数用行为动词 |
| 布尔 | is/has/can/should 前缀 |
| 类型/接口 | PascalCase，不加无意义 I 前缀 |
| 常量/环境变量 | UPPER_SNAKE_CASE；VITE_* 仅公开配置 |
| 单元/端到端 | *.test.ts(x) / *.spec.ts |
| 既有字段与枚举 | 保留冻结契约；改名走兼容变更 |

## 模块与类型

必须遵守 PROJECT_STRUCTURE。页面、组件、服务、状态、工具、评分、提示词不得混放。单功能工具留本功能；真实跨模块复用再提升。公开入口最小化，禁止 barrel 造成循环。

启用 strict/noImplicitAny/strictNullChecks；推荐 noUncheckedIndexedAccess。外部返回、存储旧值、导入文件、规则配置按 unknown 接收后运行时校验。禁止 any 泛滥、双重断言、非空断言或 ts-ignore 代替校验；必要例外须原因和收敛范围。跨端契约以 Schema 为事实源，类型派生；禁止同一契约手写两套。表单 Zod 不能成为 API 的第二份事实源。

## API、错误与日志

- 组件禁止直接 fetch 供应商；统一 client→provider/service。
- 超时、Retry-After、抖动退避、限流、取消与请求 ID 集中处理；重试仅一层负责。
- AppError 含 code/module/retryable/userMessage，原始 cause 仅受控本地诊断；用户响应不含堆栈。
- 用户提示必须给可执行操作：重试、重录、手填、跳过或降级。面试流程禁止 alert/confirm。
- 异步结果必须校验所属 session/turn，取消后的旧结果不得覆盖新状态。
- 日志只记时间、级别、模块、错误码、耗时、请求 ID 与用量；禁止正文、录音、凭证和含 token 的 URL。
- 禁止空 catch、吞错后标成功、把缺失评分默认成零或满分。

## AI、评分与密钥

系统提示词、用户输入、输出 JSON 分离。AI 输出必须 Schema+语义+证据校验；低置信度需复核；禁止编造经历、引用、概率或时间戳。规则引擎与 AI 分离，阈值配置化，扣分可解释，缺观测不扣。详细见 AI_INTEGRATION 与 SCORING_SPEC。

密钥禁止源码、VITE_*、静态资产与日志。代理密钥仅进程读取；direct 只接受用户显式提供临时凭证，不自动从代理取出。环境变量不是浏览器保密方案。详见 SECURITY。

## 测试、提交与评审

规则边界/互斥/封顶/不可观测做单元；适配器/迁移/重试做集成；供应商/AI/跨端 Schema 做契约；主流程与降级做 E2E。不得镜像实现写无意义测试。不得凭空生成题库充当审核结果。

commit：type(scope): 描述；分支 feat/fix/docs/chore。PR 必须包含版本、变更编号、影响面、契约、验证证据、隐私与回滚。评分/提示词/契约变更必须同步规范、版本和样本。未运行检查必须明确说明。
