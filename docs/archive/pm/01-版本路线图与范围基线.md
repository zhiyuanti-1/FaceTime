# 01 版本路线图与范围基线

> 文档编号：PM-01 ｜ 版本：v1.0 ｜ 状态：基线（待你确认后冻结）｜ 最后更新：2026-11-03

> **假设声明（未确认）**
> - A1：技术栈未定。1.0 假设前端 = React + TypeScript + Vite（纯静态可部署）；2.0 起假设后端 = Node/NestJS（若团队偏 Python 可换 FastAPI，接口契约不变）。
> - A2：1.0 无账号体系，单机单用户；数据仅存浏览器（IndexedDB + localStorage）。
> - A3：1.0 的"动作表现"维度**不启用**（无姿态模型），权重置 0 并归一化；动作评分从 2.0 开始。
> - A4：语音识别 = 百度短语音识别 REST；OCR = 百度通用文字识别；LLM = DeepSeek Chat Completions（JSON 输出）。
> - A5：题库为**知识点池模型**：当前 10 池 × 20 题（`stage: seed`，共 200 题），按岗位权重出 5 道八股 + 5 道简历拷打（共 10 题）；正式目标 100 题/池。不做题库管理后台。详见 [06-题库与组卷规则](06-题库与组卷规则.md)。
> - A6：里程碑为**相对周（W1 起算）**，绝对日期待你给项目启动日后再换算。

## 1. 版本总览

| 维度 | 1.0 纯前端 MVP | 2.0 后端化与本地化降本 | 3.0 公网部署 |
|---|---|---|---|
| 一句话目标 | 一个人打开网页就能完成一场"被拷打"的模拟面试并拿到报告 | 把能力搬上服务端，用本地模型替代付费 API，成本与可控性达标 | 让外部用户通过网址稳定、安全、合规地使用 |
| 用户 | 你自己 / 内测同学 | 小范围真实求职者（10–50 人） | 公开用户 |
| 技术形态 | 纯静态 SPA + 浏览器直连第三方 API | SPA + API 服务 + 数据库 + 任务队列 + 本地模型 | 容器化集群 + 网关 + 监控 + CI/CD |
| 核心能力 | 题库、简历上传 OCR、逐题作答与转写、AI 评分与追问、报告、口头禅统计 | 账号权限、服务端编排、本地 OCR/ASR、动作识别、评分参数后台、历史记录、人工复核 | 公网访问、限流、日志、隐私合规、监控告警、灰度回滚 |
| 成本结构 | 依赖第三方免费额度，单场 ≈ 0 元（额度内） | 单场 API 成本下降 60%+，新增服务器固定成本 | 按用户量线性增长，需容量规划 |
| 上线判据 | 主流程闭环 + 4 条降级路径可用 | 核心链路不依赖单一第三方 + 动作分可复现 | 压测达标 + 合规文档齐备 + 可一键回滚 |
| 预计周期 | W1–W4（4 周） | W5–W12（8 周） | W13–W18（6 周） |

## 2. 1.0 版本范围（纯前端 MVP）

### 2.1 本期做

| # | 功能 | 说明 | 验收要点 |
|---|---|---|---|
| 1.1 | 首页/模式选择 | 选择"快速练习 / 简历拷打 / 专项训练" | 3 个入口可达，空态有引导 |
| 1.2 | 内置题库（池化） | 10 个知识点池 × 20 题 seed（共 200）；按岗位权重分配 5 道八股配额；5 道简历拷打 | 同 seed 可复现、覆盖 ≥3 个主题、缺口有 warning |
| 1.3 | 简历上传 | PDF / 图片 / 粘贴文本三通道 | 三通道都能得到结构化摘要 |
| 1.4 | 简历解析（OCR） | 图片走百度 OCR，PDF 提取文本，失败可手填 | 解析失败有明确降级按钮 |
| 1.5 | 简历结构化 | 输出：基本信息、教育、工作经历、项目、技能、疑点 | 字段结构符合 `ResumeProfile` schema |
| 1.6 | 模拟面试 | 逐题：出题→作答（录音/文字）→转写→评分→追问，最多 2 层追问 | 单题闭环 ≤ 90s，可中断续答 |
| 1.7 | 语音转写 | 百度 ASR，返回文本 + 时间戳；失败降级手动输入 | 转写可编辑后再提交 |
| 1.8 | AI 评分 | 内容质量 / 简历追问 / 岗位匹配 三维（AI）；表达流畅度（规则+AI） | 每题返回结构化 JSON，可解析 |
| 1.9 | 口头禅统计 | 规则引擎统计"额/啊/嗯/那个/就是"，按分钟密度扣分 | 报告可定位到具体时间段 |
| 1.10 | 追问与拷打 | 基于简历疑点 + 回答漏洞生成追问，最多 2 层 | 追问必须引用简历原文片段 |
| 1.11 | 面试报告 | 总分、维度分、扣分项（含原因与时间戳）、加分项、改进建议、追问记录 | 可导出 JSON / 打印 PDF |
| 1.12 | 设置页 | 默认走 Vite 代理（Key 在 `.env`）；直连模式可自填 Key 并测连通性 | 代理不通时 1.5s 内切直连并提示；Key 不进 `dist` |
| 1.13 | 降级与错误处理 | 4 条降级路径 + 错误码提示 | 断网/超时/429 均有可操作提示 |

### 2.2 本期不做（红线，再提视为新需求）

| # | 不做 | 原因 | 计划版本 |
|---|---|---|---|
| N1 | 账号、登录、多用户 | 纯前端无后端，无法安全存凭证 | 2.0 |
| N2 | 服务端存储、历史记录云端同步 | 同上 | 2.0 |
| N3 | 动作/表情识别与动作分 | 无模型、无算力，且 1.0 权重已置 0 | 2.0 |
| N4 | 本地 OCR / 本地 ASR | 需要服务端或 WASM 大体积模型，与 MVP 目标冲突 | 2.0 |
| N5 | 题库管理后台 | 静态 JSON 足够 | 2.0 |
| N6 | 真人面试官对练、视频通话 | 与"AI 练习"定位不符 | 不做 |
| N7 | 支付、会员、计费 | 无商业模型 | 3.0 后 |
| N8 | 公网开放注册 | 密钥与合规均不满足 | 3.0 |
| N9 | 移动端原生 App | 响应式 Web 覆盖 | 不做 |

## 3. 2.0 版本范围（后端化与本地化降本）

### 3.1 本期做

| # | 功能 | 说明 | 验收要点 |
|---|---|---|---|
| 2.1 | 后端服务与 API 网关 | 统一入口、鉴权、限流、错误码规范 | 所有前端请求走 `/api/v1`，无直连第三方 |
| 2.2 | 账号与权限 | 注册/登录（JWT）、角色 `user`/`reviewer`/`admin`、资源归属校验 | 越权访问返回 403 且有审计记录 |
| 2.3 | 服务端任务编排 | 面试会话状态机、异步任务队列（解析/转写/评分/动作分析） | 任务可重试、可查进度、失败可见 |
| 2.4 | 本地 OCR | 替代百度 OCR（PaddleOCR 或同类），保留云端兜底开关 | 识别准确率不低于云端基线的 90% |
| 2.5 | 本地/自托管模型 | 简历摘要与追问走可控模型或小模型，DeepSeek 仅用于高价值题 | token 成本较 1.0 降 ≥60% |
| 2.6 | 动作识别 | 姿态关键点（MediaPipe/YOLO-pose）+ 规则引擎，输出动作事件流 | 事件可回溯到帧时间戳与置信度 |
| 2.7 | 评分引擎服务端化 | 规则引擎与 AI 评分分离，参数入库可配置、可版本化 | 同一输入两次评分结果一致（幂等） |
| 2.8 | 数据存储 | Postgres：用户、简历、会话、题目、回答、评分、事件、审计 | 有迁移脚本与 `schemaVersion` |
| 2.9 | 历史与对比 | 历史报告列表、多次面试趋势对比 | 可对比同岗位两次得分 |
| 2.10 | 人工复核后台 | 复核队列、单条扣分申诉、改判重算 | 改判后总分自动重算并留痕 |
| 2.11 | 隐私与留存 | 简历/录音留存期、用户删除、导出 | 删除后 24h 内物理清除 |

### 3.2 本期不做

| # | 不做 | 原因 | 计划版本 |
|---|---|---|---|
| M1 | 公网开放注册、多租户隔离 | 先内测稳态 | 3.0 |
| M2 | 计费与配额售卖 | 无商业闭环 | 3.0 后 |
| M3 | 多区域容灾 | 成本过高 | 3.0 评估 |
| M4 | 实时视频流分析（边说边评） | 延迟与算力不达标 | 3.0 评估 |
| M5 | 自研 ASR 模型训练 | 用现成开源模型即可 | 不做 |

## 5. 版本间依赖与迁移点

| 迁移点 | 1.0 → 2.0 | 2.0 → 3.0 |
|---|---|---|
| 评分引擎 | 浏览器内 TS 实现 → 服务端同构实现，**规则 ID 与阈值必须一致** | 参数集中配置中心，支持灰度 |
| 数据结构 | 前端 `LocalSession` → 服务端 `InterviewSession`，保留 `schemaVersion` 字段 | 分库分表评估 |
| 提示词 | 前端硬编码 → 服务端模板表 + 版本号 | 提示词 A/B 与灰度 |
| 密钥 | 用户自填 → 服务端托管 | KMS + 轮换 |
| 媒体文件 | 仅内存/临时 blob → 对象存储 + 签名 URL | CDN + 生命周期清理 |

**兼容承诺**：所有实体带 `schemaVersion`；前端必须能读取"低一个主版本"的数据；破坏性变更需提供迁移脚本 + 双写过渡期。
